# 遺伝子ミスセンス変異 統合評価レポート

新しく見つかったミスセンス変異を入力すると、FuncVEP・AlphaMissense・REVEL・ClinVar・
gnomAD の情報を 1 通のレポートにまとめて表示し、PDF に保存できる。

FuncVEP は Kayaalp ら, *Nature Genetics* (2026)
[doi:10.1038/s41588-026-02727-3](https://doi.org/10.1038/s41588-026-02727-3) の
変異影響予測器で、機能実験の証拠で学習されている点が既存ツールと異なる。

> **このツールは FuncVEP を再計算しない。** 著者らが公開した全ミスセンス変異
> 約 7,300 万個の予測済みスコアの表から取り出すだけなので、GPU も大規模な特徴量計算も要らない。

設計の詳細と解釈上の限界は [docs/設計書.md](docs/設計書.md) を読むこと。

## 準備（初回のみ）

### 1. 必要なパッケージ

```bash
python -m pip install -r requirements.txt
```

`requirements.txt` は動作を確認した版に固定してある（Python 3.14 で確認）。
版を上げたときは `python scripts/04_selftest.py` を走らせて NG 0 を確かめること。

### 2. データの保存先を決める

`config.yaml` の `data_root` を、**OneDrive 同期の外**にある空き 30 GB 以上の場所にする。
既定は `D:/FuncVEP`。

### 3. 参照データを取得（約 5.5 GB）

```bash
python scripts/01_download.py
```

回線によっては 1 時間以上かかる。中断しても同じコマンドで途中から再開する。
内訳だけ先に見たいときは `python scripts/01_download.py --list`。

### 4. 索引を作る（1 時間前後）

```bash
python scripts/02_build_index.py
```

途中に 11 GB の中間ファイルができる。終わったあと不要なら

```bash
python scripts/02_build_index.py --cleanup
```

で消せる（`--cleanup` を付けない限り自動では消さない）。

### 5. 学習セットを取得する（1 分、推奨）

```bash
python scripts/05_fetch_training_sets.py
```

FuncVEP リポジトリから 6 モデルの学習セット（合計 1.5 MB）を取得します。
スコアが出ない変異について「どのモデルの学習に使われたためか」を画面に
表示できるようになります。実行しなくても動きますが、その場合は理由を
示せません。

### 6. 参照データの版を記録する（数秒）

```bash
python scripts/07_write_versions.py
```

raw フォルダーのファイルから参照データの版と取得日を `index/versions.json` に書き出す。
報告書末尾の「データの版と解決経路」の節がこれを読む。参照データを取り直したら再実行する。

### PP3/BP4 の閾値について

**較正は不要です。** 論文の公表値（Supplementary Table 13）を
`data/acmg_thresholds_published.json` に同梱しており、そのまま使われます。
著者から 2026-09-05 に提供を受けた値です。

`scripts/03_calibrate_acmg.py` は手元の ClinVar から閾値を自前で算出しますが、
比較用に残してあるだけです。自前の較正は良性側で甘く出ることが分かっており
（詳細は [docs/設計書.md](docs/設計書.md) の 5 節）、通常は使いません。

## 使う

フォルダー内の **`レポートツールを起動.bat`** をダブルクリックする。黒いウィンドウが開き、
続いてブラウザにアプリが表示される。使い終わったら黒いウィンドウを閉じる。
使うたびにこの操作をする（PC を再起動すると止まっている）。
`start_report_tool.bat` は同じ内容の英語名のファイルである（GitHub で共有する際の便宜）。

ターミナルから起動する場合は次のとおり。

```bash
streamlit run app.py
```

### サーバーモード（常時起動・限定公開用）

このツールを置いた PC では、Windows にログオンすると `scripts/start_server.bat` が
自動で動き、ブラウザを開かずにアプリを待機させる（スタートアップ フォルダーの
ショートカット `MissenseReportServer` が `scripts/start_server_hidden.vbs` を呼ぶ）。
この状態では bat をダブルクリックしなくても http://localhost:8501 を開けば使える。
待ち受けは 127.0.0.1 に限り、ネットワークから直接は届かない。落ちても 10 秒後に
自動で再起動し、出力は `logs/server.log` に残る。

学内の利用者と FuncVEP の著者には、この待機中のアプリを Cloudflare 経由で
https://missense.human-genetics.uk から使ってもらう。Cloudflare Access で登録した
メールアドレスの人だけがログインでき、アプリと索引データは PC から出ない。
設定手順は [docs/限定公開_Cloudflare手順.md](docs/限定公開_Cloudflare手順.md)。

ブラウザが開いたら変異を入力する。

| 入力形式 | 例 |
|---|---|
| 遺伝子記号 + アミノ酸置換 | `BRCA1 p.Arg1699Trp` / `BRCA1 R1699W` / `TP53:p.R175H` |
| 遺伝子記号 + c. 表記 | `SDHB c.574T>C` / `SDHB c.574T>C (p.Cys192Arg)` / `SDHB p.Cys192Arg (c.574T>C)` |
| HGVS 転写産物表記 | `NM_007294.4:c.5095C>T` / `NM_007294.4(BRCA1):c.5095C>T` / `SDHB(NM_003000.3):c.574T>C` |

検査会社の報告書の書き方は幅があるので、入力の中から遺伝子記号・転写産物番号・c. 表記・
p. 表記の部品を拾って解釈する。括弧・コロン・空白・全角文字の違いは吸収する。c. と p. が
併記されていれば c. を使い、p. と食い違えば注意欄に出す。転写産物の指定が無い c. 表記は
MANE Select に当てはめ、その旨を注意欄に出す。

集団頻度は自動で取得する。gnomAD（全体と東アジア集団）の公開 API と、日本人集団の
データ（ToMMo 54KJPN、NCBN、GEM-J WGA、JGA）を集約する TogoVar の公開 API に、
変異のゲノム座標だけを送る。患者情報は送らない。gnomAD に記録が無い変異は
「収録なし（約 80 万人で観察されず）」と表示し、PM2_supporting の候補として示す。
取得できないとき（オフラインなど）は、変異の入力欄の下の「集団頻度を手入力する」に
検査報告書の値か gnomAD のサイトの値を入れると載る。サイドバーの「gnomAD を
オンラインで照会」を外すと、照会せず手入力だけで動く。

ClinVar の欄の下には「同じ残基の既知判定」を出す。手元の ClinVar 索引から、同じ
アミノ酸置換を生じる別の塩基置換（病的なら PS1 の候補）と、同じ残基の別の置換
（病的なら PM5 の候補）を拾う。通信は要らない。

このほか、オンライン照会が有効なときは次も載る（いずれも送るのは変異の座標か
遺伝子名・アミノ酸置換だけ）。

| 項目 | 出典 | 内容 |
|---|---|---|
| ClinGen の評価 | ClinGen Gene-Disease Validity（一覧 CSV を月 1 回取得） | 遺伝子と疾患の関係の確立度と遺伝形式 |
| SpliceAI | Ensembl VEP REST | 塩基置換がスプライシングを壊す確率。0.2 以上で注意欄にも出す |
| 機能実験の実測値 | MaveDB API | 大規模機能実験のスコア。実験のある遺伝子だけ節が出る |
| 文献 | LitVar2（NCBI） | 変異に言及した論文。画面だけに出し、PDF には載せない |
| ClinVar の疾患別提出件数 | ClinVar E-utilities（VariationID で照会） | 疾患名ごとの判定・提出件数・レビュー段階。ClinVar の欄を件数順にし、ClinGen の照合にも使う |

画面下の「この内容を PDF で保存」で、記録や遺伝カウンセリングに使える PDF が出る。

### 表示言語

サイドバー上部の「言語 / Language」で日本語と英語を切り替えられる。PDF は
切り替えた言語で出る。URL に `?lang=en` を付けても英語で開ける。
文字列の対訳は `funcvep_report/i18n.py` に集約してある。

## 読み方の要点

**FuncVEP が予測するのはタンパク質機能への影響であって、臨床的病原性そのものではない。**
論文の著者ら自身、この 2 つの混同を既存ツールの中心的な問題として挙げている。

この違いは抽象論ではない。本ツールで実際に得られた結果がそれを示している。

| 変異 | FuncVEP-CTI | ClinVar | 読み方 |
|---|---|---|---|
| BRCA1 p.Arg1699Trp | 0.996 Damaging | Pathogenic | 一致。3 モデルとも PP3_Strong |
| BRCA2 p.Asn372His | 0.002 Neutral | Benign | 一致。3 モデルとも BP4_Strong |
| **HBB p.Glu7Val** | **0.114 Neutral** | **Pathogenic** | 鎌状赤血球症。HbS は機能を失うのではなく**重合する**。機能喪失を測る評価系では捉えられない機序 |
| **CFTR p.Arg117His** | **0.186 Neutral** | **Pathogenic** | 蛋白機能は相当程度保たれる。発症はシスの poly-T 領域などの文脈に依存し、浸透率が可変 |

下の 2 例は **FuncVEP の誤りではない**。機能的影響と臨床的病原性は別物だ、という
そのものの実例である。機能獲得型・凝集型・浸透率可変型の変異では、機能予測が低くても
臨床的には病原性でありうる。**スコアが低いことを「病原性の否定」と読まないこと。**

### スコアが出ないことがある（2 星以上の病的変異で 11.2%）

**理由は「学習に使われたから」であって、変異が珍しいからでも、予測が難しいからでもない。**
著者に照会して確認した（2026-09-05 私信）。スコアが無いこと自体は、病原性についても
予測の信頼度についても何ら情報を持たない。

学習に使われた変異は、モデルごとに別々に推論から除外されている。その結果、
状態が 2 つに分かれる。

**① 表にあるがスコアが空欄** — 一部のモデルの学習に使われた変異。行は残り、
そのモデルの列だけが空になる。MECP2 p.Arg106Trp（Rett 症候群）、
SMAD4 p.Arg361His がこれに当たる。

**② 表に行ごと無い** — 6 モデル全部の学習に使われた変異。6 つすべての推論出力から
除かれるため、統合された最終表から消える。NEFL p.Pro8Leu がこれで、著者側でも確認済み。

FGFR3 p.Gly380Arg（軟骨無形成症）は ① と ② が同時に現れる例である。同じアミノ酸置換に
対応する塩基置換が 2 通りあり、chr4:1,804,392 の **G>A は ① の空欄**、
**G>C は ② の欠落**だった。

**よく研究された変異ほど学習に使われやすい。** 教科書に載るような有名な変異でこそ
スコアが出ない、という直感に反する挙動になる。

画面はどちらの状態かを書き分け、**どのモデルの学習に使われたか**まで表示する。
`python scripts/05_fetch_training_sets.py` を一度実行しておくと、この照合ができる。

ClinVar で 2 星以上のミスセンス変異について実測すると（`scripts/06_missing_scores_audit.py`、
2026-09-10 再実行。対象は variant_summary（2026-08-27 取得）の 2 星以上、MANE Select 上の
1 塩基置換によるミスセンスの行 63,329 件。変異としては 63,275 件で、複数の遺伝子に登録された
変異は行ごとに数えている）、

| | 対象 | 表に無い | 表にあるが空欄 | **スコアが出ない** |
|---|---|---|---|---|
| 病的 | 24,716 件 | 1,232 件（5.0%） | 1,545 件（6.3%） | **2,777 件（11.2%）** |
| 良性 | 38,613 件 | 1,716 件（4.4%） | 866 件（2.2%） | **2,582 件（6.7%）** |

**病的変異のおよそ 9 件に 1 件は FuncVEP のスコアが得られない**と見込んでおくこと。
その場合は AlphaMissense・REVEL・ClinVar の側を見る。

なお表に無い 2,948 件のうち、2,457 件（83.3%）は 6 モデル全部の学習セットに含まれ、
4 件は一部のモデルの学習セットに含まれる。残る 487 件は公開されている学習セットの
どれにも見当たらない。著者の照合（2026-09-07）では、この種の未収録に元データに無い・
注釈差による除外・処理の抜けが原因のものがあると説明されたが、個々の変異について
確定したものではない。画面では「未収録（予測表の作成上の理由。著者確認済み）」と表示し、
原因を断定しない。切り分けの詳細は [docs/設計書.md](docs/設計書.md) の 8 節にある。

### 3 つのモデルの使い分け

PP3/BP4 に用いるモデルは 1 つに事前固定している（`config.yaml` の `primary_model`、当面は
FuncVEP-CTI）。他の 2 つは段階を表示するが参考であり、一致数で強さを上げない。採用モデルに
スコアが無いときは CTE → SP の順に代替し、その旨を報告書に書く。3 つの FuncVEP モデルは
性格が違うので、揃って damaging を示すかどうかは判定のまとめで見る。

| モデル | 性格 |
|---|---|
| FuncVEP-CTI | 臨床学習済み予測器を特徴量に含む。ベンチマーク最良だが循環参照の risk が最大 |
| FuncVEP-CTE | 臨床学習済み予測器を除外。ClinVar との独立性が高い |
| FuncVEP-SP | 他の予測器を一切使わない。最も独立だが単独性能は劣る |

ClinVar に未登録の真に新規な変異では、CTI だけでなく CTE・SP との一致を確認する意味が大きい。
CTI は ClinVar 由来の情報を間接的に含むため、ClinVar と一致するのは当然ともいえる。

ACMG/AMP では **PP3/BP4（計算による証拠）** として扱う。機能データで学習してはいるが
実験そのものではないので PS3/BS3 にはならない。

対象はミスセンス変異のみ。スプライス影響・フレームシフト・ナンセンス・コピー数変化は扱えない。

## バックアップ

コードの履歴は D: ドライブのベアリポジトリに複製してある。索引データ（`D:/FuncVEP`）は
対象外で、容量が大きいうえ再作成できるため含めていない。

変更をコミットしたら押し出す。

```bash
git push backup master
```

壊れたときはここから復元する。

```bash
git clone D:/backup/missense-variant-report.git
```

このフォルダー自体は OneDrive に同期されているので、マシンが壊れても失われない。
ただし **`.git` を OneDrive に同期させると、競合でリポジトリが壊れることがある**。
その場合は壊れた状態がそのまま同期されるので、上のベアリポジトリから復元する。
バックアップ先は C: とは別の物理ディスクに置いてある。

## 困ったとき

**「AlphaMissense の索引がありません」** — `python scripts/02_build_index.py alphamissense`

**「遺伝子 XXX が MANE に見つかりません」** — 正式な HGNC 記号を使う。旧名や別名は未対応。

**「対応するゲノム座標を特定できませんでした」** — 1 塩基置換では作れないアミノ酸置換
（2 塩基以上の変化が必要）か、AlphaMissense の対象外の転写産物である可能性。
HGVS 転写産物表記での入力を試す。

**「N 番目のアミノ酸は X であり、入力された Y と一致しません」** — 参照している転写産物が
検査報告書と違う可能性。報告書の NM_ 番号を使った HGVS 表記で入力し直す。

**「残基番号の対応が一定のずれでは説明できません」** — AlphaMissense がその遺伝子について
別のアイソフォームを使っており、残基の番号がどう対応するか決められない状態。
そのまま当てはめると別の残基のスコアを示してしまうため、意図的に止めている。
HGVS 転写産物表記での入力を試し、それでも止まる場合はこの変異では本ツールを使わない。

**「その転写産物は MANE と残基番号の付き方が違います」** — 遺伝子の領域内に同じ表記の
行はあったが、それは別アイソフォーム上の同名の残基だった、という意味。同じ残基番号に
たまたま同じアミノ酸が来ているだけで、指しているのは別の場所である。採用すると
遠く離れた座標のスコアを表示してしまうため止めている。上と同じ対処をとる。

**PDF の日本語が出ない** — `config.yaml` の `pdf_font` が実在するフォントを指しているか確認する。
既定は Windows 同梱の BIZ UDP ゴシック（`BIZ-UDGothicR.ttc` と `BIZ-UDGothicB.ttc`、
`pdf_font_face: "BIZ UDPGothic"`）。無い環境では `NotoSansJP-VF.ttf` を `pdf_font` に指定する。
英語版の本文は `pdf_font_en`（既定 Arial）を使う。
既定は Windows 同梱の `C:/Windows/Fonts/NotoSansJP-VF.ttf`。
