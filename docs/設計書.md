# ミスセンス変異 統合レポートツール 設計書

対象論文: Kayaalp B, Çil K, Conil C, Cobat A, Kars ME, Itan Y, Casanova JL, Özçelik T.
*Prediction of human missense variant effects from functional evidence.*
Nature Genetics (2026). doi:10.1038/s41588-026-02727-3

---

## 1. このツールが何をするか

新しく見つかったミスセンス変異を 1 つ入力すると、次を 1 枚にまとめて返す。

- FuncVEP の 3 モデル（CTI / CTE / SP）による機能的影響の予測スコア
- 同じ特徴量を ClinVar ラベルで学習した対照モデル ClinVEP の 3 スコア
- AlphaMissense と REVEL のスコア
- ClinVar における既知の臨床的意義とレビュー状態
- gnomAD の集団頻度（手入力）と遺伝子レベルの制約指標
- 較正済みであれば ACMG/AMP の PP3/BP4 の証拠強度
- 上記の指標同士が一致しているかどうかの要約

**判定は下さない。** 指標を並べ、食い違いがあればそれを明示するところまでが役割。

## 2. なぜ「再計算」ではなく「照合」なのか

FuncVEP の学習には 580 個の特徴量（dbNSFP 由来の各種予測器、保存性スコア、
AlphaFold 構造、FoldX の ΔΔG、ESM2 の対数尤度比、遺伝子レベル指標）が使われている。
これを新しい変異について毎回計算するには数百 GB の外部データと GPU が必要で、
現実的ではない。

しかし著者らは **ヒトのあり得る全ミスセンス変異 約 7,300 万個について予測を計算し、
Zenodo で公開している**。臨床で遭遇するミスセンス変異は、参照プロテオーム上の
1 塩基置換である限りこの表に含まれる。したがって新規変異であっても

> モデルを回すのではなく、計算済みの表を引く

だけでよい。GPU も特徴量計算も不要になる。

ただし、公開表を引けば必ずスコアが得られるわけではない。当初は非標準アイソフォーム
上の変異や 2 塩基以上の変化を要する置換だけが例外だと考えていたが、**実測すると
そうではなかった**。ClinVar で 2 星以上のミスセンス変異のうち、病的で 4.9%、
良性で 4.7% がこの表に存在しない。

理由は著者に照会して判明した。**学習に使われた変異が推論から除かれているため**である
（8 節）。6 モデル全部の学習に使われた変異は行ごと消える。有名な変異ほど学習に
使われやすいので、FGFR3 p.Gly380Arg（軟骨無形成症）や MECP2 p.Arg106Trp（Rett 症候群）
のような日常的に遭遇する変異でこそ起こる。**スコアが無いことは病原性の情報を持たない。**
この場合、本ツールは理由を明示したうえで AlphaMissense・REVEL・ClinVar の側を提示する。

## 3. 中心的な設計課題と解決

### 課題: FuncVEP のスコア表はゲノム座標でしか引けない

Zenodo の予測表の実際の列は次の 8 列だけである（HTTP Range で先頭を読んで確認）。

```
ID	ensg	FuncVEP_CTI	FuncVEP_CTE	FuncVEP_SP	ClinVEP_CTI	ClinVEP_CTE	ClinVEP_SP
10-12000000-T-A	ENSG00000151461	0.7032	0.9678	0.9955	0.7263	0.5585	0.5381
```

`ID` は `染色体-位置-参照-変異`（GRCh38、chr 接頭辞なし）。
**遺伝子記号もアミノ酸変化も転写産物 ID も含まれない。**

一方、臨床の現場で使われる表記は `BRCA1 p.Arg1699Trp` や `NM_007294.4:c.5095C>T` である。
両者を繋ぐ変換が必要になる。

### 解決: AlphaMissense を座標変換の橋渡しに使う

AlphaMissense の配布ファイルは次の列を持つ。

```
#CHROM  POS  REF  ALT  genome  uniprot_id  transcript_id  protein_variant  am_pathogenicity  am_class
chr1    69094  G   T    hg38    Q8NH21     ENST00000335137.4  V2L           0.2937           likely_benign
```

`transcript_id`（Ensembl）と `protein_variant`（例 `R1699W`）を持ちながら、
同時に `CHROM/POS/REF/ALT` も持つ。つまり **アミノ酸変化 → ゲノム座標** の
対応表として使える。これで FuncVEP の表が引けるようになる。
AlphaMissense のスコア自体も第 2 の予測として同時に得られるので、二重に役立つ。

### 変換の流れ

```
[入力] BRCA1 p.Arg1699Trp
   ↓ MANE summary（遺伝子記号 → ENST / NM / ENSG / 染色体上の位置）
   ↓ MANE CDS で参照アミノ酸が本当にその位置にあるか検証
   ↓ AlphaMissense（ENST + R1699W → chr17:43091983 G>A）
   ↓
[照合] FuncVEP / REVEL / ClinVar を chr-pos-ref-alt で引く
```

```
[入力] NM_007294.4:c.5095C>T
   ↓ MANE summary（NM → ENST / 遺伝子）
   ↓ MANE CDS 配列から c.5095 の属するコドンを取り出し翻訳 → R1699W
   ↓ 以降は上と同じ
```

HGVS c. からアミノ酸変化への変換は MANE の GenBank 形式ファイルから
CDS 配列を切り出して自前で行う。外部 API に依存しない。

**検証済み**: BRCA1 c.5095C>T → R1699W、TP53 c.524G>A → R175H、
FGFR3 c.1138G>A → G380R（軟骨無形成症）がいずれも正しく変換される。

### 転写産物 ID の世代差（実測）

AlphaMissense は MANE v1.5 より古い GENCODE で作られている。実測すると、
**MANE の 19,437 転写産物のうち ID がそのまま一致するのは 13,949 件（71.8%）**
にとどまる。残り約 28% は ID が違うだけで同じタンパク質を指している。

代表例が TP53 で、MANE は `ENST00000269305`、AlphaMissense は `ENST00000445888`
を使っている。ID をそのまま突き合わせると TP53 の変異が 1 件も引けない。

対策として、索引の構築時に **転写産物 ID → 遺伝子の対応表を実測で作る**
（`index/transcript_map.parquet`）。AlphaMissense の各転写産物から座標を 25 個ずつ取り、
FuncVEP 側の `ensg` を引いてどの遺伝子に属するかを決める。根拠が座標なので
ID の世代差に左右されない。遺伝子単位で見た解決率は 94.5% になる（8 節）。

### アイソフォームによる残基番号のずれ

対応表で相手の転写産物が見つかっても、**それで安心はできない**。同じ遺伝子でも
アイソフォームが違えば残基の番号がずれるからである。MECP2 では NM_004992（486 残基）
の R168 と NM_001110792（498 残基）の R181 が同じ残基を指す。番号体系の違う相手に
`p.Arg168Cys` をそのまま当てれば、**黙って別の残基のスコアを返す**。
臨床上あってはならない誤りなので、次の二段構えで防いでいる。

1. **一致率の実測** — 索引構築時に MANE の CDS を翻訳し、AlphaMissense 側の
   `protein_variant` の参照アミノ酸と同じ位置で突き合わせて一致率を測り、
   `transcript_map.parquet` の `aa_agreement` 列に記録する。0.95 以上なら
   番号体系は同じとみなす。
2. **ずれ幅の推定** — 0.95 未満の対応について、−80 〜 +80 の範囲でずれ幅を総当たりし、
   50 残基以上を比較できてかつ一致率 0.95 以上になる幅が見つかれば
   `index/numbering_offsets.parquet` に記録する。アイソフォームの違いは多くが
   N 末端側の長さの差による一律のずれなので、これで機械的に読み替えられる。

どちらでも説明できない場合は、**番号を当てはめずに理由を示して止める**
（`Store.numbering_note`）。推測で番号を合わせることはしない。

### 予備経路と、その安全確認

対応表にも無い場合は、MANE が持つ遺伝子の染色体上の範囲を使い、その区間内で
同じ `protein_variant` を持つ行を探す。ここには落とし穴が 2 つあり、
どちらも実測で誤った座標を返していた（8 節）。

**落とし穴 1: 隣の遺伝子を拾う。** 遺伝子が重なる領域では別遺伝子の変異を掴む。
拾った座標の FuncVEP 側の `ensg` が目的の遺伝子と一致するものだけを残す。

**落とし穴 2: 同じ遺伝子の別アイソフォームを拾う。** `ensg` が一致していても、
アイソフォームが違えば同じ残基番号が別の残基を指す。しかもこれは
**参照アミノ酸の照合では防げない**。COL18A1 の 2 番残基は MANE でも拾った
転写産物でも Ala なので照合を通過し、50 kb 離れた座標のスコアを表示していた。
そこで採用前に `Store.transcript_agreement` で転写産物全体の残基一致率を測り、
0.95 未満なら採らない。

同じ理由で、**転写産物 ID が MANE と一致していても安心はできない**。対応表に
載っていない遺伝子では ID をそのまま当てているが、AlphaMissense 側の同名の
転写産物が別世代で、番号体系が違うことがある（FPGT は同じ ENST00000370898 で
一致率 0.06 だった）。この経路にも同じ検証をかけている。

それでも見つからなければ、座標を特定できなかった旨と理由を示して止める。
**推測で座標を当てることはしない。**

すべて `D:\FuncVEP` に置く。OneDrive 同期フォルダーには置かない。

### gnomAD のアレル頻度について

変異ごとのアレル頻度を完全にローカルで持つには、dbNSFP（約 50 GB、
所属機関のメールアドレスでの登録が必要）か gnomAD の巨大な VCF が要る。
そこで **gnomAD の公開 API（GraphQL）に変異ごとに問い合わせる** 方式にした
（`funcvep_report/gnomad.py`、2026-09-09）。送るのは染色体・位置・塩基だけで、
患者情報は含まない。エクソームとゲノムのアレル数を合算して頻度を出す。

結果は 3 通りに書き分ける。記録あり（頻度・ホモ接合体数、0.05 超なら BA1 該当）、
記録なし（約 80 万人で観察されず。PM2_supporting の候補。ただしその位置の
読み取り深度が不十分なら根拠にしない。品質フィルタでアレル数 0 の行も記録なし扱い）、
取得できず（手入力を案内）。手入力欄は残してあり、検査報告書の値で上書きできる。
`config.yaml` の `gnomad_af_mode` を `manual` にするか、サイドバーの
チェックを外すと照会せず完全オフラインで動く。

gnomAD の応答からは東アジア集団（eas）の頻度も取る。gnomAD v4 には日本人だけの
集団区分が無いので、日本人集団の頻度は TogoVar（NBDC/DBCLS）の REST API
（`funcvep_report/togovar.py`）から取る。TogoVar は ToMMo 54KJPN（東北メディカル・
メガバンク機構、約 54,000 人の全ゲノム）、NCBN、GEM-J WGA、JGA の頻度を変異ごとに
集約している。座標で区間検索し、塩基まで一致する 1 件から日本人集団のデータセット
だけを抜き出す。jMorp のサイトは JavaScript 描画で API の公開仕様が確認できなかった
ため、TogoVar を経由する（2026-09-10）。

残基番号の基準が違いうる注記を添える。LitVar は画面だけに出し、PDF には載せない。

### 同じ残基の既知判定（PS1 / PM5）

手元の ClinVar 索引の name 欄から p. 表記を正規表現で切り出し、同じ遺伝子・同じ
残基番号の行を集める（`Store.clinvar_same_residue`）。同じアミノ酸置換を生じる別の
塩基置換が病的なら PS1 の候補、同じ残基の別のミスセンス置換が病的なら PM5 の候補と
して示す。同義置換・ナンセンス・判定の無い行は載せない。良性判定が同じ残基にある
場合はその旨を添える。あくまで候補の提示であり、強さの判断は解釈者に委ねる。

## 5. ACMG PP3/BP4 の閾値

論文の較正値は Supplementary Table 13 にあり、**本文 PDF には含まれていない**。
2026-08-30 に著者へ問い合わせ、2026-09-05 に値の提供を受けた。
現在はこの公表値を既定として使う（`data/acmg_thresholds_published.json`）。

### 公表値（Kayaalp ら 2026, Supplementary Table 13）

PP3 は score 以上、BP4 は score 以下で該当する。

| モデル | PP3 Sup | Mod | Int | Strong | BP4 Sup | Mod | Int | Strong | 二値の境 |
|---|---|---|---|---|---|---|---|---|---|
| FuncVEP-CTI | 0.6903 | 0.8023 | 0.8583 | 0.9109 | 0.1352 | 0.0643 | 0.0262 | 0.0174 | 0.4196 |
| FuncVEP-CTE | 0.7976 | 0.8803 | 0.9370 | 0.9758 | 0.1407 | 0.0278 | 0.0171 | 0.0106 | 0.5193 |
| FuncVEP-SP | 0.7646 | 0.8933 | 0.9351 | 0.9943 | 0.1654 | 0.0803 | 0.0276 | 0.0159 | 0.4409 |
| AlphaMissense | 0.5479 | 0.8071 | 0.8794 | 0.9798 | 0.1703 | 0.1130 | 0.0973 | 0.0836 | 0.3984 |

**二値の境は 0.5 ではない。** 論文はモデルごとに異なる値を与えており、本ツールも
これに従う。原表には ClinPred と CPT1 の行もあり、同じファイルに転記してある。

原表の列見出しは `-4 -3 -2 -1 1 2 3 4` である。段階の意味は
**1=Supporting（1 点）, 2=Moderate（2 点）, 3=Intermediate（3 点）,
4=Strong（4 点）**。負は良性側、正は病的側。2026-09-07 に著者が確認した
（参照: doi:10.1016/j.gim.2025.101402）。

当初は 3=Strong, 4=Very Strong と解釈して実装しており、上位 2 段階の
ラベルと点数（最大 8 点）が過大だった。2026-09-07 の著者確認を受けて修正した。
**この体系では Very Strong（8 点）は付かない。**

### 自前の較正との差（なぜ差し替えたか）

公表値を得る前は `scripts/03_calibrate_acmg.py` で手元の ClinVar
（2 星以上、病的 17,140 件 / 良性 34,309 件）から局所尤度比法で算出していた。
この自前の値は**良性側で系統的に甘く**、3 モデルすべての全段階で公表値より
証拠を与えやすかった。CTI の BP4_Moderate は 0.155 対 0.0643 と倍以上開く。

実害は病的変異に出ていた。

| 変異 | CTI | ClinVar | 自前の較正 | 公表値 |
|---|---|---|---|---|
| BRCA1 p.Arg1699Trp | 0.996 | Pathogenic | PP3_Strong | PP3_Strong |
| TP53 p.Arg175His | 0.962 | Pathogenic | PP3_Strong | PP3_Strong |
| BRCA2 p.Asn372His | 0.002 | Benign | BP4_Strong | BP4_Strong |
| HBB p.Glu7Val | 0.114 | **Pathogenic** | BP4_Moderate | BP4_Supporting |
| CFTR p.Arg117His | 0.186 | **Pathogenic** | BP4_Supporting | 該当なし |

下 2 行は病的と確定している変異である。自前の閾値はこれらに良性方向の証拠を
与えていた。ClinVar が FuncVEP-CTI の特徴量と情報源を共有するために較正が
楽観的に偏る、という懸念が実測で裏づけられた形である。

`scripts/03_calibrate_acmg.py` は比較のために残してある。設定で
`prefer_local: true` にすると自前の値に切り替わるが、その場合レポートには
「論文の公表値ではない」と明示される。

## 6. 解釈上の限界（重要）

1. **FuncVEP が予測するのはタンパク質機能への影響であって、臨床的病原性ではない。**
   著者ら自身、既存ツールがこの 2 つを混同していることを論文の中心的な批判点として
   挙げている。機能的に damaging でも臨床的に病原性とは限らない（浸透率、遺伝形式、
   組織特異性、代償機構）。

2. **ACMG/AMP では PP3/BP4（計算による証拠）として扱う。** 機能データで学習しては
   いるが実験そのものではないため、PS3/BS3 にはならない。

3. **論文自身が、VEP スコアを ACMG 基準に組み込むと予測ツール単独より精度が下がる
   場合があると報告している**（FuncVEP-CTI 単独 84.6% に対し ACMG 適用時 79.2%）。
   機械的な当てはめではなく、他の証拠と併せた検討が要る。

4. **対象はミスセンス変異のみ。** スプライスへの影響（学習時に SpliceAI > 0.2 を除外）、
   フレームシフト、ナンセンス、イントロン変異、コピー数変化は評価できない。

5. **CTI モデルは循環参照の risk が最も高い。** ClinVar 由来の情報を間接的に含むため、
   ClinVar と一致するのは当然ともいえる。ClinVar に未登録の真に新規な変異では、
   CTE や SP との一致を確認する意味が大きい。

6. **ライセンス上、本ツールおよび変換したデータを再配布してはならない。**
   FuncVEP は PolyForm Strict License 1.0.0 で、改変と再配布を禁じ、
   利用は非商用目的に限られる（大学・公的研究機関での研究利用は明示的に許可）。
   AlphaMissense は CC BY-NC-SA 4.0、REVEL も非商用限定。
   院内・研究室内での利用に留め、公開サービス化や受託解析への組み込みは行わないこと。

## 8. 検証の記録と未確定事項

### 確認できたこと

- **HGVS c. からアミノ酸変化への変換**: BRCA1 c.5095C>T → R1699W、
  TP53 c.524G>A → R175H、FGFR3 c.1138G>A → G380R がいずれも正しく変換される。
- **座標系は GRCh38**: TP53 p.Arg175His が chr17:7,675,088 に一致する
  （GRCh37 なら 7,578,406）。ClinVar の登録内容とも一致。
- **FGFR3 p.Gly380Arg** は AlphaMissense 上で chr4:1,804,392 の G>C と G>A の
  2 通りとして登録されており、ClinVar の病的変異は G>A のほう。
  同じアミノ酸置換に複数の塩基置換が対応する場合は全て表示する設計が正しいと確認できた。
- **転写産物 ID の一致率は 71.8%**（上記 3 節）。対応表が必要である裏づけ。
- **ダウンロードの完全性**: FuncVEP の zip は 4,236,523,156 バイトで公開値と一致。
  展開後の TSV は 11,045,969,397 バイト。

### セルフテストの結果（索引構築後に実施）

`scripts/04_selftest.py` の結果は **OK 19 / 注意 6 / NG 0**。

- 注意 6 件はいずれも FuncVEP のスコアが得られないことによる。内訳は
  FGFR3 p.Gly380Arg、MECP2 p.Arg106Trp / p.Arg133Cys、SMAD4 p.Arg361His
  （およびその HGVS 表記）。いずれも学習に使われたためで、MECP2 と SMAD4 は
  一部のモデルによる空欄。FGFR3 は同じアミノ酸置換に対応する塩基置換が 2 通りあり、
  chr4:1,804,392 の G>A（ClinVar の病的変異）は 3 モデルの学習による空欄、
  G>C は 6 モデル全部の学習による欠落という、2 つの状態が同時に現れる例だった。
- 4 組の「遺伝子記号＋アミノ酸置換」と「HGVS c.」が同一の座標に到達した。
- 拒否されるべき 4 例（2 塩基変化が必要、ナンセンス、同義置換、未知の遺伝子記号）が

  うち転写産物 ID がそのまま一致するのは 13,841 件（75.7%）で、残りは座標経由の

- 残る **1,067 遺伝子**は対応表に載らず、照会時にゲノム領域での探索に回る。
- 1 件あたりの所要時間は中央値 0.09〜0.13 秒（最短 0.07 秒、最長 0.87 秒）。

#### 公開ノートブックから分かること

著者は解析ノートブックを公開している（`notebooks/`）。未収録の理由を追うため
`04_core_variant_scoring.ipynb` を読んだ。予測表を生成する処理は次のとおりである。

```python
keep_mask = ~all_idx.isin(train_idx)                  # 学習に使った変異を外す
model_scores = np.full(len(feature_matrix), np.nan)   # 全変異ぶんの器
model_scores[keep_mask] = y_pred_proba                # 予測したものだけ埋める
scores[model_name] = model_scores
```

出力 `scores` は `feature_matrix` の行から作られ、モデルごとに NaN を書き込むだけで
**行を落とさない**。公開されているコードのどこにも行を消す処理は無い。

したがって「6 モデル全部の学習に使われた変異は行ごと消える」という挙動は、
このノートブックの後段に**公開されていない後処理**（全 NaN 行の除去）があるか、
あるいは配布された表が別の実行によるものか、のいずれかである。

より重要なのは、**行の有無を決めているのは `feature_matrix.parquet` である**という点。
そしてこのファイルはコードで作られていない。`00_download_data.ipynb` は Zenodo の
`data.zip`（record 18457510、1.25 GB）を展開するだけで、特徴量行列は完成品として
配布されている。**変異の母集団をどう定義したかはコードに書かれていない。**

学習・検証セットの構築（`02_train_test_set_construction.ipynb`）には、次のコメント付きで
スプライスに影響する変異を落とす処理がある。

```python
# Drop variants with splice altering mutations
# (because we are only interested in true missense variants)
valid_ids = df_secondary[df_secondary['spliceai'].isna()]['ID']
```

これは学習・検証セットに対する処理であって予測表の生成には現れない。

#### data.zip を取得して確認した結果

`feature_matrix.parquet` は **1,117,941 行**しかなかった。7,300 万件の公開予測表とは
別物で、公開ノートブックが再現するのは core variant set の採点までである。
**公開表を生成する処理はリポジトリに含まれていない。** スプライスによる除外の仮説も、
この行数では検証できない（照会中の 491 件のうち特徴量行列にあるのは 20 件のみで、
いずれも `spliceai` は NULL だった）。

代わりに、学習セットと公開表を直接突き合わせて説明の成否を検証した。

| 学習に使ったモデル | 件数 | 表に行あり | FuncVEP 空欄 | ClinVEP 空欄 |
|---|---|---|---|---|
| FuncVEP 3 モデルのみ | 6,158 | 5,416 | 5,415 | 0 |
| ClinVEP 3 モデルのみ | 5,027 | 5,015 | 0 | 4,954 |
| 6 モデル全部 | 2,574 | **0** | — | — |

**6 モデル全部の学習に使われた 2,574 件は、公開表に 1 件も存在しない（例外ゼロ）。**
また公開表全体で 6 列すべてが空の行は **0 行**だった。著者の説明は正確である。

一方で、説明では起きないはずのことが 3 種類見つかった。

**A. 学習に使われたのにスコアが入っている変異が 62 件**（ClinVEP 61 / FuncVEP 1）。
ノートブック 04 の `keep_mask` が (ID, ensg) の組で照合しているため、公開表側の
ensg が学習セットと違うと除外が外れる。**62 件すべてが ensg 不一致で説明できた。**
重複遺伝子領域で起きている（例: 1-11027215-T-G は学習セットで ENSG00000120948、
公開表で ENSG00000009724）。学習データが評価に混入する経路であり、著者に報告する。

**B. 片方のファミリーの学習にしか使われていないのに、行ごと消えている変異が 754 件。**
説明どおりならもう一方のスコアが入った行が残るはずである。

**C. どの学習セットにも無いのに公開表にも無い変異が 487 件**（ClinVar 2 星以上、
MANE Select 上のミスセンスに限った数）。当初の疑問はここだけが残った。公開表の
生成処理が非公開である以上、手元では追いきれない。著者に照会する。

A の 62 件については、重複遺伝子の対の「もう一方の行を見ているだけ」という
可能性を潰してある。62 件はいずれも公開表に 1 行しかなく、学習セット側の ensg を
持つ行は 1 件も存在しない。ただし遺伝子の割り当てが変われば遺伝子レベルの特徴量も
変わるため、スコアが実際に影響を受けているかまでは判断できない。7,300 万件ぶんの
特徴量行列が公開されていないためである。

3 分類は `scripts/06_missing_scores_audit.py --write-list` で
`docs/funcvep_discrepancies.tsv` に書き出す（1,303 行、`category` 列で区別）。

#### 実装での扱い

`Evidence.funcvep_status` が 4 つの状態を区別する。

| 状態 | 意味 | 画面表示 |
|---|---|---|
| `scored` | スコアあり | スコアと PP3/BP4 |
| `blank` | 一部のモデルの学習に使われ、その列が空欄 | 「学習に使われたため非公開」＋使用モデル名 |
| `absent` | 6 モデル全部の学習に使われ、行ごと欠落 | 「学習に使われたため未収録」＋使用モデル名 |

ClinVEP の対照スコアが引けない場合も、その理由（ClinVEP の学習に使われた）を示す。

  **利用者の入力側の番号の付け方の違いとは別の問題**であり、そちらは未解決である。
- 公表値の列見出し `-4 … 4` を証拠強度の段階と解釈している（5 節）。単調性とは
